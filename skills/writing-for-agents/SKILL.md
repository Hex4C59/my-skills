# writing-for-agents

创建时间：未知（历史文档未记录）

修改时间：2026-10-11

编写、整理或审查 Agent 使用的文档。先理顺结构和规则，再调用 humanizer 统一检查易懂程度与 AI 套话，让人能直接读懂。保留必要解释和例子，以表达清楚为标准。

## 用途与输入

适用于 `AGENTS.md`、`CLAUDE.md`、`SKILL.md` 及代理配套文档，检查重复、过时或含糊的规则、资料引用条件、信息层级和完成标准。

输入包括目标文档、希望改善的问题和必须保留的约束；按需读取相关参考文件。例如：`$writing-for-agents 审查当前 AGENTS.md，先给出结构和表达方面的修改建议。`

## 使用步骤

1. 阅读[上游规则参考](references/writing-for-agents-original.md)，按用户指定范围检查内容。编写或修改 Skill 时，再读 [Skill 格式参考](references/SKILL-MECHANICS.md)；其中的元数据和调用说明须结合目标工具的实际支持情况使用。
2. 整理规则归属、引用触发条件和完成标准。保留适用范围、授权、失败处理及验收条件；需要解释的内容写清楚，不把多项要求挤进长句或表格。
3. 读取同级目录的 [humanizer 修改版](../humanizer/SKILL.md)，执行其中的完整流程，解释陌生术语、检查具体行为并去掉 AI 套话，保留准确含义。没有专用调用入口时，在当前代理中读取并执行该技能即可。只读审查输出表达建议，建议中的替换段落也经过润色；文件任务只写最终版本。润色阶段保持代码块、行内代码、命令、路径、YAML 和链接目标不变。
4. 对照原文复核事实、规则和引用，确认没有遗漏条件或改变要求强度。再通读一遍，检查人能否看懂谁负责、要做什么、失败后怎么办；术语和缩写须有必要解释，读起来费力的段落继续改写。按用户请求交付建议或最终文档，并如实说明检查结果。

## 依赖与输出

需要同级目录的 humanizer 修改版，无额外 Python、Node.js 或服务依赖。找不到该文件时，说明表达检查尚未完成，交付已完成的结构分析；不擅自安装，也不把自行压缩句子当作已执行该技能。

只读审查不改文件；写作任务只修改获准内容。输出为文档审查意见、修改建议或最终文档，保留用户指定的语言、格式和授权边界。

上游写作规则及 Skill 格式说明以普通文档保存在 [references/](references/)，本地修改、版本和许可证见 [SOURCE.md](SOURCE.md)。
