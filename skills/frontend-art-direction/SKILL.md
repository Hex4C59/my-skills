# frontend-art-direction

本文件是本仓库的中文收录入口。上游指令、脚本、数据和参考资料保存在 `upstream/`，固定版本与收录范围见 [SOURCE.md](SOURCE.md)。

## 用途与输入

根据产品的用户、内容、任务和现有界面确定设计方向，完成前端实现与视觉验证。

适用于应用、仪表盘、编辑器、设置页、产品官网和参考网站驱动的改版。输入包括目标项目或页面、希望改善的问题、功能与设计约束；按需提供参考网站、截图和素材。

使用示例：`请用 frontend-art-direction 审查这个应用的设置页，保留已确认的设计与功能，先报告排版和状态展示问题。`

## 使用步骤

1. 阅读[上游主 Skill](upstream/SKILL.md)，按任务选择局部润色、产品界面、表达型页面或其他适用模式。
2. 按上游指令读取当前模式需要的参考资料。原版相对链接以原版文件所在目录解析；运行包内命令时以 `upstream/` 为工作目录，通过参数指定目标项目。
3. 先检查目标项目，再确定设计方向、实施和验证；执行范围以用户当前授权及目标项目的规则为依据。
4. 根据任务交付设计判断、界面实现或审查结果，并区分源码检查、实际运行和截图证据。

## 依赖与限制

辅助脚本要求 Node.js >=18；实际实现与构建依赖目标前端项目的工具链。包内脚本没有声明额外 npm 依赖；截图工具需要目标项目已有 Playwright 或 Puppeteer。动效桥在需要时会获取固定版本的外部参考，完整设计任务还需要实际可运行的界面与截图条件。

上游对较大任务要求 20 个流程检查点和迭代记录，这些规则原样保留；本次未制作任何项目适配版。`upstream/` 按上游 `package.json` 的发布文件清单收录，另保留版本记录与贡献说明；视觉测试样例和 GitHub CI 配置不在此包中。

此目录仅用于源码收录，未安装到 Codex、pipi 或其他项目。许可证情况见 [SOURCE.md](SOURCE.md)。

## 预期输出

设计方向说明、前端改动或界面审查结果，以及与当前任务相符的截图、交互和运行证据；未验证的部分单独说明。
